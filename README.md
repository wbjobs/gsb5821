# 本地分片加密工具

纯前端大文件（1GB+）分片加密与哈希工具：分片读取 → SHA-256 分片哈希 → AES-GCM 分片加密 → IndexedDB 持久化。**不做任何上传/网络传输**，所有计算在 Web Worker 中完成，主线程保持 60fps。

## 运行

```bash
python3 -m http.server 8000
# 打开 http://localhost:8000 （Worker + ES Module 需要 http 协议，不能用 file://）
```

## 技术栈与职责

| 技术 | 用途 |
|---|---|
| File API | 文件选择、`slice()` 分片 |
| Streams API | `blob.stream().getReader()` 流式读取分片，读取中断可捕获 |
| Web Crypto | AES-GCM-256 分片加密（每片独立随机 IV）、SHA-256 分片哈希 |
| Web Worker | 全部重计算流水线，主线程只做 UI |
| IndexedDB | 会话状态（断点续传）+ 密文分片持久化 |
| PerformanceObserver | 监听 `longtask`，验证主线程无 >50ms 阻塞 |

## 关键设计

- **分片格式**：每片 `iv(12B) || ciphertext || tag(16B)`，片大小 8 MiB。
- **哈希方案**：Merkle 式根哈希 `SHA-256(concat(各分片SHA-256))`，分片顺序错误会改变根哈希，可被校验检出。
- **断点续传**：每个分片完成后将会话（`nextChunk`、全部分片哈希、JWK 密钥）写入 IndexedDB；刷新/崩溃后重新选择同一文件（名称+大小+修改时间匹配）即可续传，最终哈希不变。
- **内存控制**：严格串行流水线，单分片处理完即释放，内存占用 ≈ 2–3 个分片，与文件总大小解耦（页面实时显示 JS 堆内存）。
- **暂停/继续/取消**：Worker 控制标志 + 分片边界检查；暂停时不计耗时（基于 `performance.now()` 累计活跃时长，长时间运行不漂移）；取消立即停止并清理 IndexedDB 状态。
- **加密失败重试**：单分片自动指数退避重试 3 次，仍失败则进入错误态，由用户选择「重试」（重读本片）或「取消」。
- **文件被删除/读取中断**：流读取抛错 → 错误态提示，可重试或取消。
- **配额不足降级**：开始前用 `navigator.storage.estimate()` 预检；运行中捕获 `QuotaExceededError` 自动降级为「只哈希+加密校验、密文不落盘」模式并提示。
- **速度/剩余时间**：EWMA 平滑速度，进度按字节计算，全部基于单调时钟。

## 验收对照

1. 1GB 加密哈希：约 128 个分片串行处理，原生 `subtle` 速度下通常 1 分钟内完成，完成后展示根哈希。
2. 暂停后继续：状态逐片落盘，续传复用同一把密钥与既有分片哈希，最终根哈希不变。
3. 取消：下一个分片边界（毫秒级）停止并清理状态。
4. 内存：堆内存曲线平稳，不随文件大小线性增长（页面可观察）。
5. 顺序与校验：根哈希对顺序敏感；「校验」按钮重新逐片哈希比对。
6. 加密失败重试：自动 3 次 + 手动重试。
7. 配额不足：预检 confirm 降级 + 运行中自动降级。
8. 60fps：页面实时显示 FPS 与 longtask 统计（全部计算在 Worker，正常应为 0 次长任务）。

## 导出

- **导出加密文件**：通过 File System Access API 流式写出 `*.enc`（密文分片按序拼接）。
- **导出密钥/清单**：`*.manifest.json` 含 JWK 密钥、分片哈希、根哈希与格式说明，可用于外部解密与校验。请妥善保管。
